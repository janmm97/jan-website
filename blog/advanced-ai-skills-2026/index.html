10 advanced AI skills to learn in 2026 (beyond prompting)

November 3, 202611 min read2394 words

The advanced AI skills for 2026 are about what a model sees, what it remembers and what each run costs. They are context engineering, knowing when to compact, clearing tool results, just-in-time retrieval, agent memory, sub-agent design, tool design, evals, cost control and harness fluency. Prompting gets you started. These ten decide whether an agent stays reliable across a long session.

Key takeaways

  • The limit on an agent is its context window, not the wording of one prompt. Anthropic describes the window as a finite attention budget.
  • Compaction, tool-result clearing and a notes file keep the window small without losing what the next step needs.
  • Sub-agents and just-in-time retrieval stop one session from carrying every file it has opened.
  • Evals, cost control and harness fluency tell you whether a change helped and what it cost.

Why prompting isn't the hard part anymore

A prompt decides what you ask. Once an agent runs for many steps, what it sees matters more. The window holds the system instructions, the tool definitions, every earlier message, every tool result and any document the agent loaded. The model works from all of it on every step. Anthropic's engineering team describes context as a finite resource with diminishing returns. The model draws on an attention budget, and its ability to recall the right detail falls as the window fills. The aim they set is the smallest possible set of high-signal tokens that gets the outcome you want (Anthropic, Effective context engineering for AI agents). That changes the job. A good prompt on a bloated context still fails. A short, clean context with the right tools and the right notes often works with a plain prompt. Most of the skills below keep the window clean, and show you how to check that it is.

The ten skills, one at a time

Each skill has four parts: what it is, the failure it prevents, how to practise it this week, and how you know it's working.

1. Context engineering

What it is: choosing which tokens reach the model on each step. That includes the system prompt, the tool definitions, the conversation history and any retrieved data. The job is to find the smallest set of high-signal information for the step, not to add everything you have. Failure it prevents: a context where the fact that matters is in the window but gets less attention, because the window is full of noise. Pasting a 40-page brief to answer one question is the usual case. Practise this week: pick one agent run and list each block in its context with a rough token count. Delete the blocks this step doesn't need, run it again, and compare the answers. How you know: the same answer comes back with fewer tokens in the window, and the agent stops citing the wrong section.

2. Knowing when to compact

What it is: compaction means taking a conversation that is nearing the context limit, summarising it and starting a new window with the summary. Anthropic says the summary should keep architectural decisions, unresolved bugs and implementation details. It drops redundant tool outputs and messages. What to keep and what to drop: keep decisions, open bugs, file paths and the next step. Drop raw tool output and dead ends, once you have noted why they failed. The file paths and next step are my addition. A fresh session needs them to carry on. Failure it prevents: an agent that drifts or forgets its early instructions in a long session. Practise this week: at your next long session, write a compaction prompt, run it and check the summary against ten facts the next step needs. Count how many survived. Anthropic's advice on tuning is to maximise recall first, so the summary catches every relevant piece. Then cut superfluous content to improve precision. How you know: the summary passes the ten-fact check, and a new session continues without you re-explaining the task.

3. Tool-result clearing

What it is: removing the raw result of a tool call from the history once the agent has used it. Anthropic calls tool-result clearing one of the safest, lightest-touch forms of compaction. A tool called deep in the history rarely needs its raw output again. Failure it prevents: a search result or file dump that stays in the window for the rest of the run and crowds out the task. Practise this week: measure tokens on one run. Clear the tool results you have already used, then measure again. Keep a one-line note of what each result gave you, so the record survives the clearing. How you know: the token count drops, and the task finishes with the same output.

4. Just-in-time retrieval

What it is: keeping light references in context, such as file paths, stored queries and links, and loading the content only when a step needs it. Anthropic describes agents that keep these lightweight identifiers and pull in data at run time. Failure it prevents: loading everything at the start and burying the part the step needs. Practise this week: replace the pasted file contents in one prompt with a list of paths. Let the agent open the file it needs. Run ten tasks both ways. My practice: I keep the path list in the notes file, so a new session knows where to look. How you know: tokens at the first step drop, and the pass rate on your ten tasks holds.

5. Structured note-taking and agent memory

What it is: the agent writes notes to a place outside the context window and reads them back later. Anthropic's examples are Claude Code keeping a to-do list, and an agent maintaining a NOTES.md file. Failure it prevents: every new session starting from zero. Practise this week: create a NOTES.md with three sections: decisions, open bugs and next steps. End a session, then start a new one with only that file. My practice: I date each entry and delete it once the item closes, so the file stays short enough to read. How you know: the new session picks up the next step without a fresh explanation.

6. Sub-agent design

What it is: a focused sub-agent explores one part of a problem in its own clean context. It returns a condensed summary, which Anthropic says is often 1,000 to 2,000 tokens. The detailed search stays in the sub-agent's window. Failure it prevents: one agent carrying every file it opened and every dead end in a single window. Practise this week: hand one research step to a sub-agent. Cap its report at 1,500 tokens. Compare the lead agent's context size with a run where it did the research itself. How you know: the lead agent's window is smaller, and the answer is no worse.

7. Tool design for agents

What it is: tools with clear names, little overlap between them, and results small enough for the budget. A vague tool makes the agent guess, and a guessing agent calls the wrong tool. Failure it prevents: an agent that picks the wrong tool, or pulls 20,000 tokens when it needed two lines. Practise this week: log every tool call and its result size on one run. Find the largest result. Change the tool to return only the fields the agent uses. How you know: the largest result shrinks, and the agent calls the right tool on the first try in your test runs.

8. Evals

What it is: a fixed set of test cases you run after every change to a prompt, a tool or a compaction setting. Failure it prevents: shipping a change that fixes one case and breaks three. Without evals you can't tell whether a compaction prompt helped. Practise this week: write ten tasks with the outcome you expect. Run them before your change, then after it. My practice: I keep the ten tasks in a file next to the prompt, so every edit gets tested the same way. How you know: with the same ten tasks, you can say which version passed more.

9. Cost and latency control: prompt caching and effort

What it is: two settings the provider docs cover. Prompt caching reuses the part of a prompt that stays the same. Anthropic's docs say the cache prefix is built in the order tools, then system, then messages. Static content goes first, and the cache breakpoint sits at the end of the static part. A timestamp in the last block, for example, forces a new cache write on every request (Anthropic, prompt caching). Effort controls how many tokens the model spends on text, tool calls and thinking. Anthropic's docs suggest lower levels for simpler, high-volume work such as sub-agents, and higher levels for complex reasoning. On most models, changing the top-level effort between requests starts the cache over. Some newer models accept a per-message effort change in beta, which keeps the cache (Anthropic, effort). Failure it prevents: a workflow that works in testing and costs too much at volume. Practise this week: move the changing content in one prompt, such as dates or user input, to the end. Compare cache read tokens before and after. Then run one routine step at low effort and one hard step at a higher level. Log quality and tokens for each. How you know: cache reads go up after the move, and quality holds on the routine step at the lower effort. I give no prices here. They change by provider and plan.

10. Harness fluency

What it is: knowing how your agent tool builds its context. That means how it loads instructions, when it compacts on its own, and how it handles permissions and commands. Failure it prevents: blaming the model for a context problem the tool created. Practise this week: trace one long session. Note where the tool compacted, what it kept and what it lost. Then change one default on purpose and re-run your evals. How you know: you can point to a setting for each failure, not guess about the model.

My practice: all ten in one weekend

This is my method, not a result. I haven't published a test of it yet. I would spend one weekend on a small project you already run, in this order:

  • Saturday morning: build the ten-task eval set and record a baseline (skill 8).
  • Saturday afternoon: audit one run's context and tool results, then clear what you don't need (skills 1, 3 and 7).
  • Sunday morning: add a NOTES.md, write the compaction prompt and run the ten-fact check (skills 2, 5 and 10).
  • Sunday afternoon: try a sub-agent, move the changing content, test a lower effort level on a routine step, then re-run the evals (skills 4, 6 and 9).

At the end of Sunday, compare the baseline with the re-run. If the scores didn't move, the change wasn't worth keeping. Revert it and try the next one.

Frequently asked questions

What AI skills are in demand in 2026?

This is my view, not a survey. The skills that keep an agent reliable after the first prompt are context management, evals and cost control. I don't have a market data source for this, so treat it as my opinion.

Which AI tool is best to learn in 2026?

Pick a tool that runs in your terminal and shows you its instructions, tool calls and permissions. That lets you practise harness fluency (skill 10) on real sessions. Anthropic's examples use Claude Code, which is why this post refers to it. This is my view, not a benchmark.

What is context engineering?

It is the practice of choosing what goes into a model's context at each step. Anthropic describes the aim as the smallest possible set of high-signal tokens that gets the outcome you want (Anthropic).

When should I compact a conversation?

Anthropic describes compaction for a conversation nearing the context limit. My rules of thumb: compact at a task boundary, after a big tool dump and before the agent starts to drift. Keep decisions, open bugs, file paths and next steps. Check the summary with the ten-fact test before you trust it.

Do I need to code to learn these skills?

Not for most of them. Writing summaries, notes files, test cases and clear tool descriptions needs no code. Token logging and sub-agents go further if you run an agent tool from a terminal.
